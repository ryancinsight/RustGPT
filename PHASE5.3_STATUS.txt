GPU DETECTION BEHAVIOR (Strict, No Fallback)
================================================================================

ctx.enable_gpu_auto_detect() returns Result<()>

Priority Order:
  1. CUDA (if --features gpu-cuda)
  2. Metal (if --features gpu-metal on macOS)
  3. Vulkan (if --features gpu-wgpu)
  4. NO CPU FALLBACK (EXPLICIT ERROR)

Error Messages (Clear & Actionable):
  - "CUDA backend requires cudarc feature. Compile with --features gpu-cuda"
  - "Metal backend requires macOS + gpu-metal feature..."
  - "Automatic GPU detection failed: no supported GPU backend was detected"
  - "GPU operation '[op]' requested without GPU device attached..."

Application Responsibility:
  - Explicitly handle GPU unavailability
  - Choose CPU fallback if needed (application code)
  - No silent fallback in framework

================================================================================
POWER-OF-2 BUFFER OPTIMIZATION
================================================================================

Automatic sizing for GPU memory efficiency:

Example:
  Requested: (batch=3, embed=7, seq=5)
  Allocated: (batch=4, embed=8, seq=8)

Benefits:
  - Reduces reallocations (growth to next power-of-2)
  - GPU memory alignment (standard practice)
  - Single allocation per dimension
  - Efficient for varying batch sizes
