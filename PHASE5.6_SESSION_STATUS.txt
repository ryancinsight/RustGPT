================================================================================
ARCHITECTURE DECISIONS
================================================================================

1. STRICT GPU-FIRST APPROACH
   - auto_detect() returns error if no GPU (never fallback to CPU)
   - Pattern: all GPU operations return Result<T>
   - Simplifies troubleshooting and guarantees predictable performance

2. TWO-PASS FUSED KERNEL STRATEGY
   - Pass 1: x1=input@w1, x2=input@w2, value=x1*σ(x1), gate=σ(x2), gated=value*gate
   - Pass 2: output=gated@w_out
   - Reduces launches from 5+ to 2
   - Eliminates intermediate downloads (keep gated on GPU)
   - Benefits: 80% reduction in global memory traffic

3. MEMORY POOL REUSE (POWER-OF-2 SIZING)
   - Preallocate buffers once
   - Reuse across forward passes (zero allocation per call after init)
   - Power-of-2 sizing for cache alignment
   - Target: >92% memory efficiency

4. REFERENCE CPU IMPLEMENTATION
   - Separate CPU path for numerical validation
   - Compare GPU output against CPU with tolerance <1e-4
   - Located in richards_glu_fused_kernel.rs::forward_reference_cpu()

WORKSPACE REUSE:
  pub fn ensure_workspace(&mut self, batch_size: usize) -> Result<()> {
      if let Some(ws) = &self.workspace {
          if ws.cached_batch == batch_size { return Ok(()); }
      }
      self.workspace = Some(Workspace::allocate(batch_size)?);
      Ok(())
  }
